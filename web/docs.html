DEVELOPER REFERENCE

Structured inputs. Reproducible outputs.

Use the JSON or CSV schema below to connect an existing assessment bank to the audit engine.

Question object

Every item requires a stable ID, subject, type, prompt and supplied expected answer. Fields vary by supported type.

{
  "id": "ALG-001",
  "subject": "mathematics",
  "type": "equation",
  "prompt": "Solve 2x + 3 = 11.",
  "expression": "2*x + 3 = 11",
  "variable": "x",
  "expected_answer": "4"
}

API endpoints

GET

/api/health

Service readiness and version.

POST

/api/audits

Multipart upload with a .csv or .json file.

POST

/api/audits/preview

JSON request body: { "items": [ ... ] }. Creates a persisted audit record.

GET

/api/audits/{audit_id}

Retrieve complete findings and reviewer decisions.

POST

/api/audits/{audit_id}/reviews

JSON: item_id, decision (approved/rejected/corrected/deferred), note.

GET

/api/audits/{audit_id}/report.{pdf,csv,json}

Export the evidence record in the selected format.

For full interactive API docs during local development, open the FastAPI service at /docs. Keep the service behind HTTPS and authentication before customer data is uploaded.
