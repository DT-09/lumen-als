# LUMEN ALS — Devpost submission draft

## Tagline

A source-grounded learning environment that connects concepts, tutoring, practice and transparent learner-state updates.

## The problem

Learners often switch between course files, a chatbot, a graphing tool and a quiz without a clear link between the evidence used to explain a concept and the practice selected next. Fluent explanations can also obscure when source support is weak.

## What we built

LUMEN ALS combines a projected spatial concept universe with source ingestion, retrieval-backed tutoring, source-derived practice, a lightweight function plotter, and an inspectable topic-level estimate. The application surfaces source filenames and page/slide/timestamp locators, keeps quiz answer keys server-side until submission, and reports when the indexed material cannot substantiate a question.

Its core design principle is a **Learning Decision Trace**: the learner can inspect the submitted answer, the grading result, the expected answer and source locator, and the model estimate updated by that attempt. The trace helps expose the basis and limits of the system's decisions rather than asking learners to trust a score without context.

## How it works

1. Import supported course material and extract source-located text.
2. Search indexed passages for a question and return relevant evidence or an insufficient-evidence response.
3. Generate heuristic source-derived practice questions while keeping answer keys server-side.
4. Grade the submitted answer using explicit baseline rules and update a simple Beta(2,2)-style topic estimate.
5. Inspect current workspace counters and run the curated evaluation suite separately.

## What is technically distinctive about this implementation

The submission emphasizes inspectability: source locators, conservative evidence thresholds, server-held quiz answers, a visible grading note, an approximate uncertainty interval, and an evaluation screen that distinguishes live counters from benchmark results. The concept universe is interactive and tied to extracted concept data; it is not a prerecorded animation.

## Built with

Python, FastAPI, SQLite, PyMuPDF, python-pptx, python-docx, HTML, CSS, JavaScript, Canvas 2D, Cloudflare Pages Functions for API proxying, Docker, and AI-assisted development.

## Evaluation

Report only results generated by running `python -m pytest -q` and `python evaluate.py` on the exact submitted build. Include the fixture count, test-set construction and failure cases. The curated fixtures are small and hand-authored; they are not a general benchmark.

## Limitations and next steps

- The tutor retrieves and quotes indexed material; it is not a general-purpose generative LLM.
- Retrieval/refusal thresholds are heuristic and can produce false accepts or false refusals.
- Topic labels and question generation are heuristic; short-answer grading uses keyword coverage.
- The mastery estimate is a simple Beta-style baseline, not validated BKT/IRT or proof of retention, transfer or educational efficacy.
- The math lab plots a constrained set of functions and is not a symbolic algebra system.
- The frontend deploys to Cloudflare Pages; the Python backend requires a separate compatible host and persistent storage.
- Independent evaluation, richer diagnosis and broader subject-specific labs remain future work.
